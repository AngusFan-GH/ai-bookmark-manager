# Phase 4 开发指导：规则整理与整理建议

## 目标

在 Phase 1–3 的本地索引、受控操作和链接健康能力之上，交付默认只读的整理分析功能：发现重复书签、目录结构问题和可解释的整理建议。P4 不实现 AI Provider、Embedding、Agent Loop 或未经用户确认的原生书签写入。

## 必须遵守的边界

- 原始书签 URL 不得被规范化逻辑覆盖；规范化结果只用于比较。
- 分析服务不得直接调用 `chrome.bookmarks`；原生写入仍只能经过 `OperationPlan`、批准和 `OperationExecutor`。
- 删除、合并、移动、重命名只能生成为计划草案和预览，不能由规则或建议自动执行。
- 分析结果以持久化的 `syncState.generation` 为版本基线；同步后旧结果必须可识别为过期。
- 建议状态与分析结果分开存储，保证用户忽略的同一建议在重新分析后不会重新显示为待处理。

## 推荐模块划分

新增 `src/domain/organization/`，至少包含：

- `types.ts`：重复组、目录问题、规则、建议和分析运行状态；
- `url-normalizer.ts`：保守 URL 比较规则；
- `duplicate-detector.ts`：按 URL 分组而非全量两两比较；
- `folder-analyzer.ts`：确定性目录结构检查；
- `rule-engine.ts`：规则 dry-run、稳定优先级和冲突说明；
- `suggestion-service.ts`：建议生成、稳定指纹和生命周期；
- `organization-service.ts`：协调单次分析任务。

Repository 放在 `src/infrastructure/database/`，消息类型放在 `src/infrastructure/messaging/`。Options UI 只负责展示和发送类型化请求，Background 负责协调与持久化。

## 功能范围

### URL 与重复书签

支持完全重复、规范化重复、同目录重复和跨目录重复。默认仅规范化 hostname 大小写、默认端口和明确的跟踪参数（例如 `utm_*`、`gclid`、`fbclid`）；保留路径大小写、普通 Query、非空 fragment。带 `token`、`signature` 或 `expires` 的 URL 采用保守比较。HTTP/HTTPS、www 与非 www、不同子域名不得默认合并。

跨目录重复表示用户可能刻意分类，只能标记，不能默认建议删除。同目录重复可生成候选建议，但仍必须由用户选择并转成计划草案。

### 目录结构

至少识别空目录、单书签目录、过深目录、书签过多目录和同一父目录下的同名目录。系统根目录、书签栏和其他书签必须能正确展示，但不得被建议删除。主题混杂或目录语义合并只能使用明确的规则或启发式说明，不得宣称是 AI 判断。

### 规则与建议

规则支持启用/禁用、数值优先级、命中统计和 dry-run。首版条件可限制为域名、URL 前缀、标题关键词、当前目录和重复类型；动作只生成移动、改名、处理重复或清理空目录建议。

规则执行顺序必须稳定：优先级降序，其次规则 ID 升序。同一书签产生互斥的目标目录或标题时，必须保留冲突和理由，不得静默选择。

每条建议必须包含稳定指纹、受影响书签/目录、理由、置信度、风险等级、状态、来源和生成时同步版本。支持忽略、恢复忽略、筛选、批量选择和计划预览。

## 后台与 UI

在既有 Background Router 中新增分析、状态、取消、重复组列表、目录问题列表、规则 CRUD/预览、建议列表、忽略/恢复及“建议转计划草案”消息。所有输入需要校验并返回已有统一错误结构。

分析启动返回 `runId`；状态返回 `status`、`processed`、`total` 和可选错误；取消后不能将部分分析标记为完成。Options Page 新增“智能整理”入口，至少提供概览、重复书签、目录分析、规则管理和建议列表/预览。

## 完成方式

1. 先核对现有数据模型、Router 和 `OperationPlan` 能力，再设计新增类型与 schema。
2. 先实现 URL Normalizer、Duplicate Detector 与 Folder Analyzer 的纯函数逻辑。
3. 加入规则、建议生命周期和 Dexie 持久化。
4. 接入后台消息、取消和状态查询。
5. 最后接入 Options UI 与计划草案预览。

## 验收与验证

本阶段以功能完整、可运行和人工验收为主。开发完成后至少运行 `npm run typecheck`、`npm run lint`、`npm run test` 和 `npm run build`；测试只需覆盖新增核心能力和明显安全回归，不以覆盖率、压力测试或浏览器 E2E 为硬性目标。

人工验收应确认：分析能完成；重复组和目录问题可查看；规则可保存并生成可解释建议；忽略状态在重新分析后保留；建议只能创建计划草案，未批准前没有原生书签变化。若浏览器环境不可用，必须明确记录未验证项。
