# Task-first workspace 0.3

## User journeys

- The main task input returns local matches before consented, cancellable MiniMax enrichment. Local-only operation remains available.
- The latest validated answer owns one stable-ID reference list. Previous turns remain accessible rather than duplicating every result card.
- The popup prioritizes capture, checks existing native bookmarks first, and never waits for AI before saving.
- Virtual topic views derive from validated AI folder/move proposals and fresh source records. They are explicitly views, not browser-folder mutations. New physical structures can still be proposed through reviewed plans.
- Similar-title/same-site groups are metadata-only inspection candidates, not proof of equivalent content or deletion targets.
- Batch review shows operation counts and supports dependency-safe exclusions through a regenerated preview. Native source and duplicate-survivor evidence are checked before preview and execution.

## Evidence and privacy

Task context retains the user's objective/refinements and prior displayed IDs. Outbound candidate disclosure stays bounded. Full local provenance remains available for privacy checks even when outbound history is compacted. Excluded or changed historical data invalidates unsafe continuation rather than silently retransmitting it.

Health checks retain dated method/status observations. Repeated 404/410 observations are not a claim of permanent loss. Bounded local heuristics can flag suspected login or soft-404 pages; they are not MiniMax judgments and never authorize deletion. Page bodies used by health classification are transient, not stored or sent to a model.

The transport never sends credentials and never silently follows an uninspected redirect. Only explicitly textual content is read, up to 64 KiB. Browser-hidden redirect targets remain unverified. Missing permissions, rate limits and network failures are not dead links.

## Verification boundaries

The browser harness uses a temporary synthetic extension profile and controlled network interception. Its health matrix exercises native browser fetch and the production adapter while serving fixture responses, not arbitrary public sites or the user's actual bookmark library. Assertions require service-worker-origin interception and fail rather than falling back to mocked fetch responses.

The separate MiniMax acceptance uses synthetic data at the service layer. Browser/provider fixture tests and live provider tests are complementary, not a claim that every real page and corpus has been tested.

## Explicit limits

- No external embedding service, general semantic-dedup engine, or autonomous corpus-wide background analysis was added. Virtual themes currently require validated organization proposals; metadata similarity is not content equivalence.
- Soft-404/login detection is conservative local title/heading/form evidence and can miss localized or JavaScript-rendered pages. HTTP success does not prove useful content.
- MV3 in-memory health scans do not automatically resume across worker termination. Persisted completed checks remain available and the UI explains this boundary.
- Native change guards compare source title, URL and direct parent. Virtual-topic freshness additionally compares path. Ancestor-only renames are not currently a native-plan invalidation criterion.
- Recovery is operation compensation with conflict checks, not an unconditional whole-library overwrite.

Final test counts, CI revision, screenshots and installation archive should be taken from the completed run for the exact delivered commit, not from intermediate development checks.
